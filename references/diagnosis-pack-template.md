# 诊断资料包模板

使用以下固定结构，保证小晚能先读摘要，再按需查看证据。

```text
诊断资料包_客户代号_YYYY-MM-DD/
├── 00_诊断摘要.md
├── 01_业务与当前阶段.md
├── 02_产品用户与增长证据.md
├── 03_问题决策与已有尝试.md
├── 04_资源约束与执行条件.md
├── 05_材料索引与资料缺口.md
└── 附件/
```

## 通用写作规则

- 使用用户认可的代号，不默认写真实姓名或公司全称。
- 文件索引只使用代号、脱敏后的显示名或相对路径，不写入本机绝对路径。
- 保留原始数字口径、单位、时间范围和来源。
- 事实不足时写“未知/待补”，不要补全。
- 把用户观点写成“用户当前判断”，不要伪装成外部事实。
- 对冲突信息并列记录，并注明需要在诊断中确认。
- 不在资料包中给出最终定位、完整GTM方案或增长承诺。
- 摘要控制在两页以内，其余文件以事实密度优先。

## 完成检查

生成文件后确认：

- `00_诊断摘要.md`可以独立说明现状、决策和准备度。
- 所有重要数字都有时间范围和来源。
- 真实事实与用户解释没有混写。
- 资料缺口没有被猜测填补。
- 至少确认一个关键决策和一个执行负责人；未确认时明确标红为阻塞项。
- 没有密码、Token、完整联系方式或无关第三方隐私。
- 没有本机绝对路径、本机账户名或无关项目目录名。
- 附件索引可以找到原始证据。
